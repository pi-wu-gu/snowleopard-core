## 〇、"无界面、被依赖"对开发流程的四条直接影响

| 定位 | 对开发的影响 | 具体做法 |
|---|---|---|
| **无任何界面** | 不能像星期五那样靠真机自测看界面；一切行为只能从**返回值/文件/审计**验证 | **测试 100% headless**——这是好事：星期五每轮回归要起客户端 3.5 分钟，本项目全部检查应该是秒级 |
| **无任何界面** | 草案里的"二次确认"（笔记删除、纠错移除）**不能做成对话框、也不存在外部审批方**（21:38 用户更正：是**确认**不是审批，**发给模型自身**，相关组件只服务于模型自己） | 实现为**两段式工具调用**：首段返回待删内容 + 确认令牌，**模型自己**带令牌二次调用才执行。core 内闭环，零 UI、零外部决议 |
| **被外部模组调用** | 是依赖组件：API 稳定性 > 功能速度 | **冻结 API 清单**先行（M1 就定）；语义化版本 + `core_api` 号；单 jar 零依赖 |
| **只是决策核心** | 决策 = 工具调用的门禁/编排/记忆，**不做呈现、不做输入采集** | 输出通道只有三个：工具返回值（含四级结果）、文件系统（ID 家）、审计日志。没有第四个 |

**继承星期五的三问判据**（判断一个类该不该进 core）：
① 少了它 `ask()` 这条链能不能跑完？② 换一个宿主要不要改它？③ **它有没有界面/文案**？
——本项目第 ③ 问的答案永远必须是"没有"，出现"是"就说明放错了地方。

## 一、目标产物与明确不做

### 1.1 产物

```
snowleopard-core（单 jar，纯 Java 21，零第三方依赖）
├─ agent-loop        主循环 / 轮次 / 预算 / 触发分发
├─ tool-registry     工具组注册表 + 限定名/重名消歧 + 搜索索引
├─ storage           ID 文件夹 / 挂载隔离 / caller_id 解析 / 时间戳写入
├─ config            两级工具配置 + 权限配置（WARN/ERROR 分级）
├─ result            四级结果（OK/WARN/SEVERE/ERROR）
├─ builtin-groups    会话管理 · 记忆 · 任务清单 · 笔记（全部无界面）
└─ contracts         冻结 API：ToolGroupProvider / HostServices / Result / …
```

`mod-shell-neoforge`（薄壳，允许 MC 知识）：生命周期接线、模组工具组发现（Provider SPI）、
配置文件平台读写。**core 的 CI 加 `jdeps` 检查：无 `net.minecraft`/`net.neoforged` 引用**。

### 1.2 明确不做

- **任何界面/渲染/输入采集**（草案里的"面板/对话框"语义全部翻译成契约与文件）
- **子模型（subagent）**——可被组合出来，不进核心
- **MC 耦合**——那是其他工具/模组的事
- 墙钟定时器（记忆压缩是惰性的，挂轮末检测，见可行性分析 §10.5）

## 二、工程骨架（第一天就定）

```
雪豹决策核心/
├─ docs/                          # 可行性分析 + 本流程 + 交付记录（带时间戳）
├─ src/main/java/                 # core 产品树（全量编译，无编译锚点）
├─ src/check/java/                # headless 检查器（不进 jar；包名不变只挪路径）
├─ src/modshell-neoforge/         # 模组壳（独立编译单元，依赖 core）
├─ tools/                         # 内置工具组清单（JSON：简介/详解/参数 schema）
├─ build.sh                       # 全量编译 + check all + publish
├─ VERSION
└─ config/                        # 示例配置（权限样例、工具配置样例）
```

**构建纪律**（星期五的坑直接绕开）：

1. `javac @sources.txt` **全量编译**（相对路径、在项目根执行）——不搞编译锚点清单，
   新增类天然进产物（星期五曾因锚点漏登记让 `RuleApprover` 整类缺失）。
2. 检查器住 `src/check/java`，`build.sh check` 自动加 `-sourcepath`。
3. `check all` 是**唯一**回归入口，每次提交前跑；全部检查必须秒级。
4. 检查器命名 `FooCheck`，`check <name>` 不带 Check 后缀。

## 三、接口先行：M1 就要冻结的契约

依赖组件的 API 就是产品。以下接口在 M1 定稿并写"冻结清单"（改 = 升 `core_api`）：

| 契约 | 用途 | 关键点 |
|---|---|---|
| `ToolGroupProvider` | 外部/模组注册工具组 | `describe()`（组名/简介/详解/分类/触发/可用性三档）+ `backend()`；注册强制带 `source`（`builtin:`/`local:<gid>`/`mod:<modid>`） |
| `ToolBackend` | 工具实现 | `invoke(ctx, args)`；`ctx` 只读携带 **`caller_id`**（core 注入、模型不可伪造）；工具无 `ids/` 路径拼接权 |
| ~~`Approver`~~ | — | **不存在此契约**（21:38 更正）：删除/纠错的二次确认是**发给模型自身**的，做进 Result 与工具协议（两段式调用 + `confirm_token`），不暴露宿主回调 |
| `HostServices` | 宿主提供的外围 | 日志、（可选）LLM 客户端注入点；**不含任何 UI 方法** |
| `Result` | 四级结果 | `ok(data)` / `warn(data, desc)` / `severe(data, desc)` / `error(desc)`；**非 OK 必须带描述**（构造期强制） |
| 清单 schema | `tools/*.json` | name/summary/usage+params（工具详解=结构化字段）/risk/reversible/availability/triggers/config_schema |

**三问自查**：每个新接口过一遍〇节的判据；出现"返回给玩家看的文案"就地改成结构化数据。

## 四、开发里程碑（每步可独立验收、独立发布）

依赖顺序来自可行性分析 §七，展开成 M0–M7。**每完成一个 M，跑 `check all` + 归档证据（带时间戳）**。

### M0 · 骨架与工程设施（半天）

- 目录、`build.sh`（全量编译 + check 框架）、`VERSION`、`jdeps` 零 MC 检查、首个 `check smoke`
- **验收**：`./build.sh && ./build.sh check all` 绿；产物类数 = 源文件推算数（无漏编）

### M1 · 地基：ID / 重名 / 存储 / 工具配置 / 挂载隔离（分析 §2.1+§二.四+§九）

- `Ids`：ID 家解析（`ids/<ID>/`）、`caller_id` 注入通道、**路径锚定**（越界 ERROR）
- `Names`：限定名 `<来源类型>:<来源ID>:<组名>` + 短名解析（歧义不猜、返回候选）+ 别名表
- `Storage`：挂载点管理（默认挂调用 ID、互相隔离、桶按需创建）
- `ToolConfig`：两级来源（ID 自带 `tools-default.json` ← `tool-configs/` 启动引用）、
  单文件全覆盖、没写=默认、匹配失败=WARN、参数错误=ERROR；键用全名
- **验收**（headless）：重名四场景（唯一/歧义/别名/同全名拒载）；路径越界被拒；
  两会话不同 ID 同工具并发互不可见；配置三语义各一发；**ID 不伪造**（模型侧传 ID 参数被忽略/拒）

### M2 · 注册表 + 注入 / 查询 / 搜索（分析 §一、§二、§三）

- `ToolRegistry`：装载（内置 → `local` 目录 → Provider SPI）、来源标注、`availability` 三档
- 自动注入：组简介进上下文（便宜）、工具详解走统一查询入口 `tool_help`（按需）
- `tool_search`：简介/详解关键词 + 按来源过滤；**禁用工具搜得到名字、搜不到详解**
- **验收**：注入体积断言（组简介注入、详解不注入）；搜索命中/来源过滤；坏清单（`broken_demo`）拒载留 ERROR

### M3 · 权限 + 结果四级 + 触发（分析 §二.五、§二.六、§二.七）

- `Permissions`：默认启动（全权限 ID0）/ 指定 ID（输入文件优先）、未启用仅可见名称、
  `ALWAYS_ON/NORMAL/DEFAULT_OFF` 三档（禁 ALWAYS_ON → 配置失败）、热更新（只影响之后的调用）
- `Result` 四级落地 + 非 OK 强制描述
- `TriggerRegistry`：主动唤起（必须回应）/ 会话始末 / 轮始轮末；确定序（组全名字典序 + priority）；
  被动触发失败按分级记录不杀主链（内置 WARN/ERROR、模组可 SEVERE）
- **验收**：权限三档各一发（含"禁内置组被拒"）；热更新不回溯；触发顺序确定性；内置工具 SEVERE 仅出现在真"带伤运行"场景（预算耗尽收束、修复残留缺口），别处不出现

### M4 · 三个小自带组：会话 / 任务 / 笔记（分析 §三.一、三.三、三.四）

- 会话管理（ALWAYS_ON）：`session_yield`（结束本轮不触发下次发送）、轮次/消耗上限、
  当轮总消耗/上句消耗/余量/轮次消耗自动注入（无上限显示"无上限"不是 0）
- 任务清单：增删条目/子条目、标记完成/受阻/失败（子条目删除=标记不删，真删走 `purge`）
- 笔记：建夹/建文/读/追加/删除（**删除走两段式自确认 + 回收站** `notes/.trash/<ts>/`：首段返回待删清单+`confirm_token`，模型带 token 二次调用才执行）
- **验收**：yield 后主循环确实不再发下一轮；预算超限自动收束；笔记删除无 token 不生效、token 与内容不匹配被拒

### M5 · 记忆组（最大件，拆四步单独验收，分析 §三.二 + §8 + §10.5）

| 子步 | 内容 | 验收要点 |
|---|---|---|
| M5a 双根存储 | `memory/`（压缩链）+ `memory-raw/`（轮原始 JSONL：`{seq,ts,kind,payload}`）；桶按需创建 | 无调用日不产任何档；原始条目可 `seq` 次路由 |
| M5b 轮压缩 | 每轮结束检测 → LLM 压缩入天档（进消耗统计）；失败 WARN + **冷却补做** | 失败不静默；空日跳过 |
| M5c 分级压缩 | 天→周→月→季→年（自然季 + ISO 周）；**惰性**（轮末检测/启动 catchup 补做）；年记忆完整加载 | 周总结只汇存在的天档；空周末不补 |
| M5d 纠错 + 完整性修复 | 纠错条目（双时间戳、两段式自确认、读取自动加载）；`memory_repair`（判据"**原始在、压缩缺**"） | 空档**不**报缺口；孤儿纠错条目 WARN；纠错移除需 token 二次确认 |

- **验收**：三层默认加载（年完整 + 紧邻存在的档 + 未压缩有记录层）；周一 00:05 取周日、周日空则往前；
  `memory_repair` 在"有原始缺压缩"上修复、在"空日"上零动作

### M6 · mod-shell + Provider SPI（分析 §四）

- NeoForge 壳：生命周期接线、`ToolGroupProvider` 发现（ServiceLoader/事件）、来源 `mod:<modid>` 标注、
  配置文件平台读写
- **验收**：外部测试工具组经 SPI 注册且带来源；`jdeps` 仍零 MC（检查的是 core）；`core_api` 不匹配拒载

### M7 · 加固（分析 §4.3、§10）

- 模组卸载 → 注销其组 + WARN；已在执行的调用允许完成
- 启动报告（生效配置来源、配置失效汇总、重名消歧表、工具组来源分布）
- 文档检查（`check docs`：使用类文档不提废弃符号、工具名存在、清单工具被文档覆盖）
- **验收**：注销后调用报"工具不存在"而非崩溃；WARN 汇总进报告

## 五、测试策略（无界面红利：全部秒级 headless）

| 层 | 手段 | 对照星期五 |
|---|---|---|
| 单元/契约 | `src/check/java` 的 `*Check`（断言意图不断言现状；关键断言先注入验证会红） | 同左，但**无需真机** |
| 并发/隔离 | 双 ID 并发、同 ID 内资源锁、caller_id 防伪 | 星期五 `check concurrent` 经验直接搬 |
| 集成 | 以"假宿主"（内存 HostServices + 脚本 LLM）跑完整 `ask()` 链 | 星期五用 `ScriptedProvider` 同法 |
| 模组壳 | 唯一需要"起游戏"的部分 → 只在 M6/M7 做少量真机冒烟 | 星期五 106 键真机自测收窄到壳层 |

**断言纪律**（继承）：先造场景再断言；断言"画出来的"不只"算出来的"；改输出格式全仓 grep 旧断言；
工具失败必须抛异常/进 ERROR 级，**绝不假成功**；测试状态放实例字段（可变 static 守卫）。

## 六、工程纪律（从星期五带过来的坑清单）

1. **工具失败必须走 Result.error / 异常**，绝不返回看似成功的文本。
2. **全量编译**，无编译锚点；新增类不需要登记。
3. **同一职责单点收口**：开关归权限文件、参数归工具配置文件；路径解析只有一处。
4. **时间戳进一切记录**（原始条目、压缩档、纠错双时间戳、审计、配置生效快照）。
5. **相对路径以 `core.base_dir` 为基准**（路径基准差一层的教训）。
6. **断言的层级要对准**：测 id 行为按 id 取，不取"第一个"。
7. **改异常类型全仓 grep 捕获点**。
8. **追加式写文档必自相矛盾 → 每轮追加后从头校对**。
9. **遇到未知情况先问，不连续猜测**（用户明确要求）。

## 七、版本与发布

- `VERSION`（semver）+ 清单里的 `core_api`（契约版本，独立演进）。
- 发布 = `./build.sh publish` 出单 jar → 宿主（模组）以依赖引用；模组壳可 jarjar 内嵌 core。
- 破坏性契约变更 = 升 `core_api` + 在冻结清单记变更时间戳；旧宿主装载时**明确报错**而不是静默降级。
- 每个 M 完成：`check all` 绿 → 文档/证据归档（带时间戳）→ 提交。
