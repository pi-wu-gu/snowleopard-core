# 内置工具组（六组）：会话 / 记忆 / 任务 / 笔记 / 唤醒 / 群组

> 2026-10-23 19:40 (UTC+8) · 对象：雪豹决策核心 0.4.0 · 验收：`./build.sh check builtin`（42 条）
> 规范来源：「分析 §三」（分析 = `docs/工具组支持可行性分析-2026-10-22.md`）
> 本文是**使用类文档**：新增/改工具先改这里，再改 `BuiltinGroups`，最后补 `BuiltinCheck`。

## 一、为什么住在 core，以及"接进注入面"是什么意思

六组（会话 / 记忆 / 任务清单 / 笔记 / 唤醒 / 群组）是**决策核心自身的能力**，与 Minecraft 无关（分析 §4.4）。
前四组是**核心组件的数据面**（红线 3：不跨 ID 复用信息）；后两组是**协作面**（2026-10-23 20:50 裁决例外，
受"零路径参数 / 鉴权在 core / caller_id 不可伪造"三条约束，见概念地图 §三·补）。
它们此前只有 Store（能力层），没有清单（schema），于是**模型看不见、也调不到**——能力存在但不进上下文，
等于零。本版把它们接进注册表的**两级注入面**：

| 面 | 方法 | 内容 | 成本 |
|---|---|---|---|
| 便宜的那份（每轮进上下文） | `ToolRegistry.briefs()` | 分类 + 全名 + **组简介** | 4 行 |
| 按需的那份（模型主动查） | `ToolRegistry.help(name, aliases)` | 组详解 + 每工具 usage/参数 | 单次查询 |

**分界即省 token**：组简介进上下文，工具详解不主动注入（"单轮 92% 预算花在工具介绍上"的解法，分析 §一.1）。

注册走**与外部 provider 同一条**路径（`ToolGroupProvider` → `ProviderLoader.load`），
来源 `builtin:core:*`，限定名由装载器拼——内置组**没有特权通道**，否则会退化成"绕过注册表的影子能力"。

## 二、六组清单（32 工具）

| 组全名 | 可用性 | 工具 | 说明 |
|---|---|---|---|
| `builtin:core:session` | **ALWAYS_ON**（不可禁用） | `session_yield` · `session_usage` | 主动收束本轮 / 用量（当轮·上句·余量·轮次） |
| `builtin:core:memory` | **ALWAYS_ON** | `memory_read` · `memory_default` · `memory_correct` · `memory_repair` | 分级读取（含轮内次路由）/ 默认加载 / 纠错 / 完整性修复 |
| `builtin:core:todo` | NORMAL | `todo_add` · `todo_add_sub` · `todo_mark` · `todo_list` · `todo_delete` · `todo_purge` | 子条目一层；父删=标记，`purge` 才物理删 |
| `builtin:core:notes` | NORMAL | `note_mkdir` · `note_create` · `note_append` · `note_read` · `note_search` · `note_delete` | 创建/追加分开（破坏性 vs 安全）；删除进回收站 |
| `builtin:core:wake` | NORMAL | `wake` · `wake_status` · `wake_deny` · `wake_policy` | 协作面：请另一个 ID 开工（在运行则失败，不排队） |
| `builtin:core:group` | NORMAL | `group_create` · `group_disband` · `group_add` · `group_remove` · `group_grant` · `group_leave` · `group_send` · `group_read` · `group_list` · `group_search` | 协作面：三级角色（创建者＞管理＞成员），消息 append-only，不跨网络 |

`builtin:core:memory` 组的 `memory_read(level, period, [sub], [all])`：`level` 取 `day|week|month|quarter|year|round`，
期号形如 `2026-10-23` / `2026-W43` / `2026-10` / `2026-Q4` / `2026`；`level=round` 时 `period` 传轮档名，
带 `sub` 定位轮内单次思考/调用（次路由）。

**稀疏性**（记忆组的硬约束）：原始记忆必须调用过才产生——空档是常态，不补、不报缺口、不参与"紧邻"取值。
所以 `memory_read` 读到不存在的期号返回 ERROR 并**明说"该期无调用则无档"**，不是故障。

## 三、执行面（宿主怎么调）

注册表只装 schema；**执行**走 `BuiltinToolkit`，一次装配一个实例，只认**当前调用 ID 的家**：

```java
SnowLeopard core = SnowLeopard.bootstrap(storageRoot, SnowLeopard.Options.allowAll());
SnowLeopard.CallerScope scope = core.forCaller("alpha");      // ID 由 Ids.Caller 校验，不可伪造

BuiltinToolkit kit = scope.tools();                            // 或 new BuiltinToolkit(scope)
Result r = kit.call("todo", "todo_add", Map.of("text", "写文档"));
```

`BuiltinHome` 是执行面的能力来源接口（由 `SnowLeopard.CallerScope` 实现）——放接口不放门面类型，
是为了让依赖方向单向（门面 → 内置包），避免包级双向依赖。
**两种失败不许混为一谈**：

| 情形 | 返回/抛出 | 谁的问题 |
|---|---|---|
| 未知工具名、缺参数、非法枚举值 | `Result.Error`（带可选值或"先 tool_search"提示） | **模型输入** |
| 未知组名 | IllegalArgumentException（宿主装配错，抛） | **宿主装配**（路由表错） |
| 文件不存在、路径非法 | `Result.Error`（Store 原有文案） | 环境/输入 |

## 四、两段式确认（发给模型自身的确认）

`note_delete` 与 `memory_correct` 都是**两段式**：首段只回预览 + `confirm_token`（**不落盘**），
带令牌二次调用才生效；令牌绑定内容摘要——两段之间改过内容，旧令牌失效。

```
note_delete(path)                      → Ok{confirm_token, preview}      （未删）
note_delete(path, confirm_token=…)     → Ok{deleted, moved_to}           （移入 notes/.trash/<时间戳>/）
```

`memory_repair` 同理只补"**原始在、压缩缺**"的段；"日历上有洞"不算缺口（空档不是欠账）。

## 五、权限：自带默认 vs 外部设置

草案原文"无外部设置即使用其自身默认设置"。落地为 `Permissions.fromFiles` 的一条规则：

- 权限文件**没提到** `builtin:*` 组 → 按自带默认（注册默认开）——否则用户文件只列模组时，
  core 自己的会话/记忆/任务/笔记会全灭；
- 权限文件**明确关**的是普通组（`todo`/`notes`）→ 真的关（提到即表态）；
- `ALWAYS_ON`（`session`/`memory`）被写禁用 → 记 ERROR "配置失败" 并忽略（配置不许把核心能力关掉）。

`Options.allowAll()` 走 `Permissions.defaultAll`：`allOpen=true`，对**之后注册**的组同样放行。

## 六、红线与边界（改代码前先看）

1. **跨 ID 一律禁止**：工具只碰 `BuiltinHome` 给的这一个 ID 家的 Store；`BuiltinCheck` 用两个 ID
   交叉验证（别人的待办/笔记看不见）。
2. **失败必须是一个失败**：不许把失败包成 `Result.Ok`（星期五"假成功家族"的教训）。
3. **清单即政策**：加工具要同时改 `BuiltinGroups`（schema）与 `BuiltinToolkit`（执行），
   只改一处 = 模型看得见调不通（或调得通看不见）；`BuiltinCheck` 第 7 段锁"清单数 == 注册数 == 18"。
4. **SEVERE 不强加**：内置组以 OK/WARN/ERROR 为主，只有"预算收束"与"修复残留"两处真算带伤运行。
5. 笔记**不进**记忆的被动检索——要查用 `note_search`（分析 §三.四 的设计决定，别"顺手"接进注入链）。

## 七、本版没做的（明确记账）

- **六组全部已接壳**（框架 v1.3.0 / M10，真机 122 步 0 FAIL）：`builtin:core:session|memory|todo|notes`
  自 v1.2.0 起可用；`wake`/`group` 在 v1.3.0 接通——运行态权威由 `LockFileRuntime` 注入核心（壳与核心共用
  同一实例），待执行请求经 `pending()` 可见。
- **唤醒的执行端不在壳里**：框架没有 LLM 会话驱动，所以 `WakeBridge.rejectUnrunnable` 会明确回写
  `failed` 并给原因，**不提供"假装执行"的路径**；真正的执行属于外部宿主（星期五那一层）。
- 工具组的**参数配置**（`ToolConfig` 两级：ID 自带 / 外部引用）本版未接这六组。

## 八、协作面两份的额外约束（裁决落地）

| 组 | 关键裁决 | 落地形态 |
|---|---|---|
| `wake` | 已运行则失败、不排队 | 六道闸：ID 合法 → 非自唤起 → 非成环 → 深度 ≤ 1 → 目标不在运行 → 未被拉黑；`depth` 由 core 注入 |
| `wake` | 黑名单属**被唤起方** | `ids/<目标>/wake-policy.json`，语义"我不接受谁唤起我" |
| `group` | 新增"管理"权限级别 | 三级角色；`group_add` 需管理+创建者，`group_grant` 仅创建者 |
| `group` | 引用，源丢失/变更报失败·过期 | `ref.state = ok / stale / missing`，**只回状态不回内容** |
| `group` | 解散不轻删 | 群目录移 `shared/groups/.recycled/<ts>-<gid>/` |
| 两者 | 提示在 `TURN_END` 汇总一行 | 无未读且无唤起 → silent（不占上下文） |
