## 一、生命周期图（一次外部调用的一生）

```
外部模组实现 ToolGroupProvider（只给：coreApi / sourceId / Descriptor）
        │  describe(): 组短名+简介+分类+可用性+工具清单
        ▼
ProviderLoader.load ──校验 coreApi==Version.CORE_API，不等→拒载
        │  限定名由装载器拼： <来源类型>:<来源ID>:<组名>   ← provider 不构造
        ▼
Names 注册（重名消歧）──► ToolRegistry 注册（briefs 简表 / help 按需详解 / search）
        │
        ▼
Permissions 门禁（Table 不可变快照；reload 不回溯）
        │  放行后：
        ▼
Ids 定位 caller 的家： home(caller) → resolve(caller, rel)   ← 跨 ID 一律拒绝
        │
        ▼
执行（Todo/Note/Memory/Session/Confirm 等自带能力）
        │
        ▼
Result 四级返回： Ok | Warn | Severe | Error   ← 非 OK 必须带描述（构造期强制）
        │
        ▼
StartupReport.render： 来源分布 · 消歧表 · WARN 汇总
```

> 标准入口可用装配门面 `SnowLeopard.bootstrap`（两级句柄：root 级 + `SnowLeopard.CallerScope`，
> 见接入指南 §二）——门面只调公开 API，**展开即上图**；上图同时是手动装配（进阶）的配方。

## 二、术语表

### 命名与来源（Names / Version）

- **限定名**（qualified name）`<来源类型>:<来源ID>:<组名>`——工具组的全局唯一标识，由装载器拼接，provider 无权构造（防冒名）→ `Names.Qualified`
- **短名**（short name）——限定名最后一段，即组名；同短名多来源即歧义 → `Names.ambiguous()`
- **短名歧义**（short-name ambiguity）——同短名多来源时**不猜**；resolve 返回 `Names.Resolution` 三态：Found（唯一命中）/ Ambiguous（歧义带候选）/ NotFound → `Names.resolve`
- **别名定向**（alias targeting）——**歧义短名**允许用别名显式指向某个全名；**唯一短名**拒收别名（遮蔽本来明确的名字）；同键冲突/指向不存在的全名都拒 → `Names.validateAliases`
- **来源类型**（source type）——BUILTIN（core 自带）/ MOD（模组）/ LOCAL（外部目录，清单须带稳定 gid）→ `Names.SourceType`
- **coreApi 契约号**（coreApi）——provider 声明的契约版本；与 `Version.CORE_API` 不等即拒载（宁拒不猜兼容）→ `Version.CORE_API`

### 隔离与身份（Ids）

- **ID 家**（ID home）——每个模型 ID 一个家目录 `ids/<ID>/`，**所有工具的工作目录默认挂在调用 ID 下、互相隔离**；审计目录与工具产物分开（工具不可写删）→ `Ids.home`
- **caller_id**（caller id）——调用方身份，由 core 从调用上下文注入、**不可伪造**（不是工具参数）→ `Ids.Caller`
- **跨 ID 禁止**（cross-ID forbidden）——工具只是功能复用、**不复用信息**；跨 ID 访问一律拒绝（含只读）→ `Ids.resolve`（锚定家目录）
- **路径逃逸**（path escape）——`../` 之类试图离开家目录的路径，解析即抛 → `Ids.PathEscape`

### 注册与配置（ToolRegistry / ToolConfig / Permissions）

- **装载 / 注销**（load / unregister source）——装载：manifest JSON 或 SPI descriptor 进注册表；注销：按来源整批移除（模组卸载、短名随之释放）→ `ToolRegistry.loadManifest` / `ToolRegistry.unregisterSource`
- **两级配置三语义**（two-level config）——工具配置：ID 自带 ← 外部引用覆盖；**没写=默认静默、匹配失败=WARN、参数错误=ERROR** → `ToolConfig`
- **可用性**（availability）——ALWAYS_ON（禁用尝试被拒）/ NORMAL / DEFAULT_OFF（默认禁用，名字可见）→ `ToolRegistry.Availability`
- **简表 / 详解**（briefs / help）——briefs=注入用简介清单（不含详解）；help=按需取单工具详解；缺名报「工具不存在」→ `ToolRegistry.briefs` / `ToolRegistry.help`
- **门禁表**（permissions table）——每组每工具的允许集；**热更新不回溯**（不可变快照，新调用生效）；ALWAYS_ON 护栏不许配置关掉 → `Permissions.Table` / `Permissions.reload`

### 返回契约（Result）

- **四级结果**（four-level result）——Ok（照常给数据）/ Warn（数据+描述）/ Severe（**部分**数据+描述）/ Error（无数据只有原因）→ `Result`
- **带伤运行**（SEVERE）——仍能运作的降级态，**不是 Error 的别名**；只用于预算收束与 memory_repair 残留两处，不需要不强加 → `Result.Severe`
- **假成功禁区**（false-success ban）——失败必须走 Error 或抛异常，**禁止把失败文本包进 Ok**（星期五的 `"[failed]"` 事故）；非 OK 构造期强制带描述 → `Result`

### 会话与确认（SessionGate / ConfirmGate）

- **会话门**（session gate）——轮次/消耗双上限记账、`session_yield` 收束判定与停止原因 → `SessionGate`
- **无上限**（unlimited）——预算 -1 的显示形态（注入行显示「无上限」而不是 0）→ `SessionGate.Budget`
- **注入行**（injection line）——自动注入的一行用量：当轮/上句/余量/轮次四数字 → `SessionGate.injectionLine`
- **二次确认 / 确认令牌**（confirm_token）——发给**模型自身**的确认（两段式调用，无外部审批方）：令牌绑内容摘要、单次使用、TTL 10 分钟、**动作不符不烧令牌** → `ConfirmGate`

### 记忆（RawLog / MemoryStore / Periods / Rollup / Corrections）

- **轮**（round）——一次思考及调用；每轮一个 JSONL，键=结束时间戳 `round-yyyy-MM-dd_HHmmss`（UTC+8）→ `RawLog.Round`
- **次路由**（entry routing）——按（轮键, seq）寻址读单条记录 → `RawLog.readEntry`
- **稀疏记忆**（sparse memory）——**原始记录必须调用过才产生**；无调用日=不存在：空档不补、不报缺口、不参与「紧邻」取值 → `MemoryStore`
- **双根**（dual roots）——`memory-raw/`（原始轮档）与 `memory/`（压缩档）分开 → `RawLog` / `MemoryStore`
- **平级五层周期**（flat five-level periods）——日/周/月/季/年**平级**不嵌套（ISO 周跨月，嵌套树必错）→ `Periods.Level`
- **三层加载**（default load）——年档完整 + 紧邻**已完成**一级 + 未吸收部分 → `MemoryStore.loadDefault`
- **轮压缩 / 归档**（rollup）——压缩由 LLM 做（宿主注入 `Compressor`，失败抛异常），core 不含模型 → `Rollup` / `Compressor`
- **惰性压缩**（lazy rollup）——周期翻转挂**轮末**检测，不需要墙钟定时器 → `Rollup.onRoundEnd` / `Rollup.catchup`
- **冷却补做**（cooldown retry）——压缩失败=丢当次产物、记 WARN、进冷却（5 分钟），下轮末或启动时重试；原始记录永远还在 → `Rollup.COOLDOWN_MS`
- **完整性修复**（memory_repair）——判据是「**原始在、压缩缺**」，不是「日历有洞」；可触发修复，残留缺口=带伤运行 → `Rollup.repair`
- **纠错**（corrections）——对已有记录的纠正：两段式删除、双时间戳、孤儿挂起 → `Corrections`

### 工作存储与触发（TodoStore / NoteStore / TriggerRegistry）

- **一层子任务**（one-level subtasks）——任务只允许一层父子，不再往下嵌 → `TodoStore`
- **标记删除**（soft delete）——delete=标记 DELETED 不物理删；`purge` 才物理清除；mark(PENDING)=恢复 → `TodoStore.delete` / `TodoStore.purge`
- **两段式删除 + 回收站**（two-phase delete）——笔记删除先入 `.trash/` 再定夺，带 `confirm_token` → `NoteStore`
- **触发钩子**（trigger hook）——挂在调用点的钩子，按（优先级, 全名）**确定序**执行，坏钩子不杀主链 → `TriggerRegistry.Hook`
- **启动报告**（startup report）——启动可见性三件套：来源分布、消歧表、WARN 汇总 → `StartupReport.render`

## 三、接入红线（违反即设计错误）

| # | 红线 | 兜底 |
|---|---|---|
| 1 | **非 OK 必须带描述**——Warn/Severe/Error 无描述直接抛 | `Result` 构造期强制 |
| 2 | **provider 不构造限定名**——只给组短名与 sourceId，全名由装载器拼 | `ProviderLoader.load` 能力上收口 |
| 3 | **跨 ID 一律禁止**（含只读）——功能复用不复用信息 | `Ids.resolve` 锚定 + `Ids.PathEscape` |
| 4 | **失败不许伪装成功**——走 `Result.Error` 或抛异常，禁止失败文本进 Ok 数据 | 测试断言 + 代码评审 |
| 5 | **coreApi 不匹配即拒载**——宁拒不猜兼容 | `ProviderLoader.load` 显式校验 |
| 6 | **caller_id 不可伪造**——core 从调用上下文注入，永远不是工具参数 | `Ids.Caller` 构造约束 + 评审 |

补充约定（非红线但同权重）：工具组必须带简介（summary）与详解（usage+params）；记录一律带时间戳
（`YYYY-MM-DD HH:MM (UTC+8)`）；中文不进标识符。
