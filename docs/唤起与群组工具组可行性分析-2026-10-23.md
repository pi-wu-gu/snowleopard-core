## 二、"唤起"到底是谁的动作（这一条定错，后面全错）

core 是**零依赖单进程库、没有主循环**——它没有能力"让某个模型开始跑"。所以职责必须切开：

| 谁 | 做什么 |
|---|---|
| **core** | 登记 `WakeRequest`（含 from/to/prompt/reason/depth/ts）；校验黑名单、自唤起、递归、深度；给出"已受理 / 已在运行 / 被禁 / 成环"四种裁决；写审计 |
| **宿主** | 实现 `RuntimeView.isRunning(id)`（运行态权威）；`poll()` 取待执行请求 → **真正启动一次会话** → 回写 `state=done/failed` |

**为什么不能"core 自己推断在跑"**：`SessionGate` 只有轮次与用量，没有"存活"概念；
拿 `yielded/turns>0` 推断会误判（上一轮结束但进程仍在跑 → 以为空闲 → 双开同一 ID）。这是"两个实例抢同一 gameDir" 那类事故的翻版。

**定案（2026-10-23 21:30 裁决）：双保险，缺一不可**——
1. 进程内 `Map<String, WakeRequest>` + 每 ID 一把 `synchronized` 状态；
2. 跨进程 `<id>/run.lock`（FileLock）——两个进程抢同一 ID 时**第二个必然失败**，正是草案要的语义。

**不做排队**：草案要"已在运行则失败"，排队会把"失败"悄悄变成"稍后执行"——隐式并发，比失败更坏。

## 三、唤起：递归、预算与黑名单（草案没写但必须有）

### 3.1 递归与环
- `depth` 由 **core 注入**（不可伪造，同 `caller_id`）；**深度上限 = 1（裁决定案）**：被唤起方**不得再唤起任何 ID**——
  预算稀缺，一层够用；要链式推进的话，被唤起方应当用自己的判断做完，而不是把预算再转手；
- **环检测**：请求链上的 ID 集合（A→B→A）立即拒，报"唤起链成环"；
- 自唤起：`from == to` 直接拒（不是"在运行"，是非法）。

### 3.2 预算不做穿透
被唤起方跑起来用的是**自己的** `SessionGate` 预算；唤起不携带"代为消耗"的额度，
也不能改对方上限（改预算=重建会话）。被唤起方预算耗尽照旧收束——否则唤起就是绕过预算的后门。

### 3.3 黑名单（"禁止唤起自身列表"）

| 项 | 定义 |
|---|---|
| 归属 | **被唤起方**的家：`ids/<to>/wake-policy.json`（含义：我不接受谁唤起我） |
| 工具 | `wake_deny(model_id, on=true)` / `wake_policy()` |
| 校验时机 | 发起时 core 读**被唤起方**策略（共享面合法跨 ID 读，零路径参数） |
| 默认 | 空 = 谁都能唤起；每次唤起都记审计，事后可拉黑 |
| 自唤起 | 恒拒，不受列表影响 |

**容易搞反的地方**：草案写"添加/取消指定 ID 到禁止唤起自身列表"——主语是**被唤起方**。
若做成"发起方的黑名单"（我不唤起谁），那是另一个功能（且没意义：模型自己不发请求就行）。

### 3.4 工具清单（`builtin:core:wake`，4 个）

| 工具 | 签名 | 说明 |
|---|---|---|
| `wake` | `wake(model_id, prompt?, reason?, client_req_id?)` | 发起；**失败即失败**（在跑/被禁/自唤起/成环/深度超限） |
| `wake_status` | `wake_status(req_id)` | 受理后查结果（宿主执行完回写） |
| `wake_deny` | `wake_deny(model_id, on=true)` | 拉黑 / 取消拉黑（改的是"我的"策略） |
| `wake_policy` | `wake_policy()` | 我的黑名单 + 最近被唤起记录（含 from/reason/结果） |

### 3.5 失败形态（全部 `Result.Error`，带原因与来源）

| 情形 | 返回 |
|---|---|
| 目标已在运行 | `目标 X 正在运行（运行态来源：宿主 RuntimeView / 锁文件）` |
| 目标禁止我唤起 | `目标 X 已禁止你唤起它（wake-policy 命中）` |
| 自唤起 | `不能唤起自身` |
| 成环 | `唤起链成环：A→B→A` |
| 深度超限 | `唤起深度超限（当前 2，上限 1）——被唤起方不得再唤起` |
| 宿主未实现运行态 | `运行态未知：宿主未提供 RuntimeView——拒绝放行（不猜"没在跑"）` |
| 目标 ID 不存在 | `目标 ID 未登记：xxx` |

## 四、本地群组

### 4.1 存储布局（append-only 是硬要求）

```
snowleopard/shared/groups/
├── index.json                    # 群组表（gid → {name, creator, createdTs}），单写者维护
└── g00012/
    ├── meta.json                 # 同一份（单群可独立读，免扫全表）
    └── messages.jsonl            # append-only：一行一条消息，seq 即行序
snowleopard/ids/<模型>/groups/
└── state.json                    # {gid: {joinedTs, lastReadSeq, notifiedSeqs[], muted}}
```

**为什么 append-only**：群组是"多 ID 同时写"的写面。邮件组当初用 `index.json` 读整表改写，
在多写者下就是覆盖竞态；`messages.jsonl` 只追加、读用 `since_seq` 游标，天然无覆盖。
`seq` 的分配与 append 必须在**同一临界区**（否则重号）。

并发：进程内每群一把锁 + 跨进程 `FileLock`；解散与发送竞态按"先落盘者赢"（解散后发送 → `群组已解散`）。

### 4.2 逐条落点

**群-1 创建**：`g<seq>` 从 `index.json` 分配；创建者自动入组；群名可重（gid 才是标识）；
上限：每 ID 创建 ≤ 20 群（防刷）。

**群-2 解散（仅 creator）**：`creator` **由 core 从创建记录取**，绝不接受调用方声明的 creator；
解散 = 群目录移入 `shared/groups/.recycled/<ts>/`（与"不轻删"一致；彻底删由维护工具做，不给模型）。

**群-3 添加 ID（裁决定案：新增"管理"权限级别）**

角色三级，权限按级递增（**不是**"任何成员都能拉人"）：

| 角色 | 谁能给 | 能做什么 |
|---|---|---|
| **创建者**（creator，唯一） | 建群即定，**不可转让、不可伪造** | 解散、移除 ID、**任命/撤销管理**、添加 ID |
| **管理**（admin，裁决新增） | 仅创建者可任命（`group_grant`） | **添加 ID**、发消息、读、搜索 |
| **成员**（member，默认） | 被添加即为此级 | 发消息、读、搜索、自己退出（`group_leave`） |

- `group_add` 需要 **管理或创建者**（"除普通成员外均可添加"）；
- 被加者可用 `group_leave` 自救（草案缺这条，**必须补**——否则被拉进群无路可退）；
- 创建者不能 `leave`（否则群无人负责）：报 `创建者不能退出，请先解散群组`；
- 拉人/任命/移除全部记审计（谁对谁做了什么）。

**群-4 移除（仅 creator）**：成员表是权威——移除后立刻读不到新消息；其 `state.json` 保留（历史可查）。
被移除者若原本是管理，角色一并清除（不留悬空权限）。

**群-5 发送（可带文件）→ 改写为"文字 + 引用"（裁决定案：引用，源丢失/变更报失败·过期）**

`group_send(gid, text, ref?)`：
- `ref` 只能是**发送方自己家内**的引用（笔记路径 / 工具产物名），过 `Ids.resolve` 锚定，跨 ID 一律拒；
- 发送时对引用做**快照**：`{owner, relPath, kind, sha256, bytes, ts}` 存进消息（此后源文件怎么变都不影响已发出的消息）；
- **收取方拿不到别家的内容**（红线：核心数据不复用信息）——`group_read` 只回 `ref` 的**状态**，不回内容；
- 状态三档：

| 状态 | 判据 | 返回 |
|---|---|---|
| `ok` | 源文件存在且 `sha256` 一致 | `ref:{owner, relPath, state:ok}` |
| `stale`（过期） | 源文件存在但 `sha256` 变了 | `ref:{…, state:stale, note:"引用的是发送时的版本，内容已变更"}` |
| `missing`（失败） | 源文件不存在 | `ref:{…, state:missing, note:"源文件已丢失"}` |

**引用失效不影响消息本身**——正文是发送时的文本副本，仍可读；失效只如实标在 `ref` 上（"报失败/过期"而不是静默当没引用）。
想让别人看到内容，就写进 `text`；**不做隐式内容外泄**。

**群-6 读取未读**：`group_read(gid, limit, since_seq?)` → 返回消息列表并推进 `lastReadSeq`；
只读已落盘行（不受并发影响）。

**群-7 搜索**：`group_search(gid, keyword, since_ts?, until_ts?, limit)`——朴素子串（大小写不敏感）+ 时间窗，
限单群 5000 条内线性扫；**索引留 v2**（倒排=新存储层，现在不引）。

**群-8 存在未读自动提示**：`TURN_END` 注入**一行汇总** `群组未读：g12(5) g7(1)`；无未读 → `silent`。

**群-9 新增消息提示（仅一次）**：`notifiedSeqs` 记"已提示过的 seq"——与 `lastReadSeq` 分开；
否则"提示过但没读"的消息会永远不再提示。

**群-10 不跨网络**：`shared/groups/` 下无 net 维度；消息若引用外来内容，标 `⚠非同源`（v1 仅引用本 ID 内容，天然不涉及）。

### 4.3 成员资格与内容可信度
- 读前校验：`state.json` 有 gid **且** 成员表含本 ID，否则 `ERROR 非成员不可读`；
- 群消息是**别的模型写的文本**——与外来邮件同一类注入面：`group_read` 返回带
  `[群组消息 · 非同源指令]` 前缀，且**不自动全文注入**（提示只给计数）。

### 4.4 工具清单（`builtin:core:group`，9 个）

| 工具 | 签名 | 权限（裁决后的三级角色） |
|---|---|---|
| `group_create` | `group_create(name)` | 任何 ID（每 ID ≤ 20 群）；建群者=创建者 |
| `group_disband` | `group_disband(gid)` | **仅创建者** |
| `group_add` | `group_add(gid, model_id)` | **管理 + 创建者**（"除普通成员外均可添加"） |
| `group_remove` | `group_remove(gid, model_id)` | **仅创建者**（原管理体系一并清除） |
| `group_grant` | `group_grant(gid, model_id, role=admin\|member)` | **仅创建者**（任命/撤销"管理"） |
| `group_leave` | `group_leave(gid)` | 本人（创建者不可退：先解散） |
| `group_send` | `group_send(gid, text, ref?, client_msg_id?)` | 成员及以上 |
| `group_read` | `group_read(gid, limit=20, since_seq?)` | 成员及以上 |
| `group_list` | `group_list()` | 本人（我的组 + 未读数 + 我的角色） |
| `group_search` | `group_search(gid, keyword, since_ts?, until_ts?, limit=20)` | 成员及以上 |

### 4.5 附件门槛（若将来要做真附件，先过这五关）

1. 内容寻址存 `shared/groups/<gid>/blobs/<sha256>`（同文件多群共享一份，不重复占盘）；
2. 单文件 ≤ 256 KB、每群总量 ≤ 16 MB、类型白名单（md/txt/json/png）；
3. 读取要成员校验，且**只回内容不回路径**（零路径参数原则）；
4. 附件内容同样是不可信外来内容（带标记、不自动注入）；
5. 超限**拒绝并报错**，不静默截断。

结论：**v1 不做**（"不需要不用强加"）。先做 `ref` 引用，真有人需要再说。

## 五、两个功能的接缝：一块共享面，五个对象

| 共享对象 | 路径 | 写者 | 读者 | 鉴权 |
|---|---|---|---|---|
| 群组表 | `shared/groups/index.json` | 单写者（锁） | 全员（gid 目录用） | 无（不含内容） |
| 群成员 | `meta.json` 的 `members[]` | creator（移除）/ 成员（添加） | 成员 | 成员资格 |
| 群消息 | `g*/messages.jsonl` | 成员（append） | 成员 | 成员资格 + 可信标记 |
| 唤醒请求 | `shared/wake/<reqId>.json` | 发起方 | 宿主 / 双方 | 双方可见 |
| 唤醒策略 | `ids/<id>/wake-policy.json` | **本人** | 发起方（读，不可写） | 只写自己 |

**提示必须汇总成一行（裁决定案）**：`TURN_END` 是所有组共用注入点（会话/记忆/群组/唤醒都会想说话）。
多个组各占一行会把尾注撑大——**同一注入点必须统一装配**（这条是"谁后加谁覆盖"的预防：
星期五那边多控件渲染抢位置的教训，同构）。汇总形态示例：

```
提醒：群组未读 g12(5) g7(1) · 新唤起 2 次（1 已完成）· 记忆待吸收 3 段
```

## 六、风险表

| 风险 | 形态 | 对策 |
|---|---|---|
| **唤醒风暴** | A 唤起 B，B 唤起 C…或 A 高频唤起 B | depth ≤ 1 + 环检测 + 滑动窗口配额（每 ID 每小时被唤起 ≤ 20，超限 ERROR） |
| **预算穿透** | 用唤起绕开自己的预算 | 唤起不代付额度；被唤起方预算照旧生效 |
| **群组刷屏** | 单群消息爆炸 / 单条巨长 | 单条 ≤ 4 KB、每群 ≤ 5000 条（滚动归档）、每 ID 每分钟 ≤ 30 条 |
| **共享面越权** | 非成员读 / 被移除者读 / 冒充 creator | 成员表权威 + creator 从创建记录取（不收参数） |
| **注入** | 群消息是别的模型写的指令式文本 | 不自动全文注入 + `[群组消息 · 非同源指令]` 标记 |
| **并发** | 两 ID 同时发 → seq 重号 / 覆盖 | append-only + 每群锁 + seq 与 append 同临界区 |
| **竞态** | 解散与发送同时发生 | 先落盘者赢；解散后发送 → `群组已解散` |
| **审计缺失** | 唤起/建群/拉人/移除无记录 | 全部记审计（工具不可写删） |

## 七、验收断言草案

**WakeCheck（约 14 条）**
```
① 目标空闲 → 受理（state=pending）② 目标在跑 → ERROR 带"运行态来源"
③ 自唤起 → ERROR ④ 成环 A→B→A → ERROR ⑤ depth 超限 → ERROR
⑥ 黑名单命中 → ERROR（且是"被唤起方"的列表生效，不是发起方的）
⑦ 拉黑后取消 → 恢复可唤起 ⑧ 未实现 RuntimeView → ERROR（不猜没在跑）
⑨ 目标不存在 → ERROR ⑩ 幂等：同 client_req_id 重复 → WARN 不产生第二条
⑪ depth 不可伪造（参数传入 depth 被忽略）⑫ 审计有记录
⑬ 配额窗口：第 21 次唤起 → ERROR ⑭ 宿主回写 done 后 wake_status 可见
```

**GroupCheck（约 32 条）**
```
① 创建 → g<seq> 单调 ② 建群者=创建者且自动入组 ③ 上限 20 群
④ 解散仅创建者（非创建者 → ERROR）⑤ 解散后发送 → ERROR ⑥ 解散进 .recycled
【角色三级（裁决定案）】
⑦ 普通成员 group_add → ERROR（"除成员外均可添加"的反面）⑧ 管理 group_add → Ok
⑨ 任命管理仅创建者（管理自己任命 → ERROR）⑩ 撤销管理后再 add → ERROR
⑪ 被移除者的管理角色一并清除 ⑫ 创建者 leave → ERROR（先解散）
⑬ 被加者可 leave 自救（退出后读 → ERROR）
⑭ 发消息 seq 递增且落 messages.jsonl（盘上断言）⑮ 同 client_msg_id 幂等
⑯ read 推进 lastReadSeq ⑰ 重复 read 不重复推进 ⑱ 非成员读 → ERROR
【提示（裁决定案：汇总一行）】
⑲ 未读提示与唤醒结果在同一条注入行里 ⑳ 无未读且无唤起 → silent
㉑ 提示一次（notifiedSeqs）：提示过但未读，下轮不再提示、未读计数仍在
【引用三态（裁决定案）】
㉒ 源未变 → ref.state=ok ㉓ 源被删 → ref.state=missing（"源文件已丢失"）
㉔ 源被改 → ref.state=stale（"内容已变更"）㉕ 引用失效不影响正文可读
㉖ 跨 ID ref → ERROR（只能引用自己家内）㉗ ref 只回状态不回内容（红线）
【其它】
㉘ 搜索子串命中 ㉙ 搜索时间窗 ㉚ 单条超 4 KB → ERROR
㉛ 群消息带非同源标记 ㉜ 并发两 ID 发送 seq 不重（含审计有记录）
```
