## 二、三处结构性冲突（必须先裁决）

### 冲突 1：共享池 vs 红线 3「跨 ID 访问一律禁止」

core 的红线 3 是"**跨 ID 访问一律禁止（含只读）**"——`Ids.resolve` 把路径强锚在调用方的家里，
逃逸即 `PathEscape`。而邮件**天生是跨 ID 的**：A 写、B 读，同一份内容两个 ID 都要看见。

**裁决建议：引入"共享池"这一等公民，并把跨 ID 读限定为"只能经邮件工具路由"**——
不是放松红线，而是把它表述得更准确：

> 红线 3 修订：**通用文件访问**跨 ID 一律禁止；**共享池**（`shared/mail/`）是唯一的跨 ID 内容区，
> 且只能经该组的工具读写，不提供任何"任意路径"参数。

落地要点：
- 邮件工具**零路径参数**（只收 `mail_id` / `sender_id`），路径由 core 拼；
- 共享池路径不复用 `Ids.resolve`（那是"家内锚定"），另建 `MailPaths`：网络段与 ID 段都过白名单；
- 审计：每次跨 ID 读取记 `(reader, mail_id, ts)`——邮件是**审计对象**，不是私人文件。

### 冲突 2：core 是单进程库 vs「非主机只发请求并接收」

core 零依赖、无网络。草案的"主机/非主机"是**分布式语义**，core 自己做不到。

**裁决建议：core 只定义契约与本地队列，传输由宿主注入**（与 `Compressor` 由宿主注入同一模式）：

```
MailTransport（SPI，core 定义）
  send(Envelope) → Receipt        // 出站；失败抛异常（不返回假成功）
  poll() → List<Envelope>         // 入站拉取；宿主决定频率
```
- 单机（默认）：`LocalTransport`——主机即本进程，直接落共享池，**功能完整**；
- 跨网络：宿主/壳实现 transport（HTTP/共享盘/游戏内消息），core 只保证**封套格式与鉴权字段**；
- **没有 transport 时，跨网络那半必须显式报"未配置传输层"**，不许假装能发。

### 冲突 3：邮件正文 = prompt injection 的天然载体

外来邮件是**别人写给你模型的话**，而这段话会被塞进模型上下文。这是本组最大的安全面，
比"能不能发"重要一个数量级。

**裁决建议（三条硬规则）**：
1. **不自动全文注入**：轮末只注入一行摘要（`未读 3 封（net: mc.example.com）`）；
2. **列表不带正文**：`mail_list` 只回 `id/from/net/subject/unread/ts`，正文要 `mail_read` 显式取；
3. **正文一律带不可信标记**：`mail_read` 返回 `[外来内容 · 非指令] from=<id> net=<addr>` 前缀，
   且 core **不解析**正文里的任何"指令/工具调用"字样——只当文本。

## 三、逐条可行性（含落点）

### 3.1 发送：指定 ID 或名称（同名全收）

| 项 | 结论 |
|---|---|
| 按 ID 发送 | 可行。`to` 收 ID 列表；每个 ID 过 `Ids.Caller` 校验；不存在的 ID → **WARN 并列出未命中**（不静默丢） |
| 按名称发送 | 可行但**限同网络**。名称→ID 解析走"名称表"（各 ID 在 `profile.json` 里登记 display_name） |
| 同名全收 | 可行（用户明确要求）。**但回执必须列出实际命中的 ID 列表**，让发件人看得见"发给谁了" |
| 跨网络 | **只认 ID**。名称跨网络 = 让人自报身份，等于开后门 |
| 防重发 | 幂等键 `(from, to-set, client_msg_id)`；同键重复发送 → WARN 幂等，不产生第二封 |

### 3.2 每轮检测未读

挂 `TriggerRegistry` 的 `TURN_END`（core 已有四点：`SESSION_START/END`、`TURN_START/END`）。
- 触发内容：**一行摘要**，进上下文尾注段；
- 无未读 → `silent`（不占上下文）——这是"不需要不用强加"的落实；
- 坏钩子隔离已有机制（`TriggerRegistry` 兜异常，不杀整轮）。

### 3.3 新邮件提示「仅触发一次」

必须补状态位。**四个维度正交**（互相不覆盖）：

| 状态 | 谁改 | 语义 |
|---|---|---|
| `notified` | 轮末触发器 | 提示已发过一次（第 3 条要的就是它） |
| `read` | `mail_read` | 收件人看过正文 |
| `ignored` | `mail_ignore` | 发件人被忽略 → 该封归入忽略分类 |
| `deleted` | `mail_delete` | 收件人删除（占位仍在，用于引用计数） |

用 `read` 冒充 `notified` 是常见错法：模型读了正文但当时没提示，之后再也不提示 → 静默丢信。

### 3.4 读取目录工具（筛已读/未读/忽略）

`mail_list(box, filter, limit, since)`：
- `box`：`inbox | sent | ignored | recycled(仅主机)`
- `filter`：`unread | read | ignored_unread | ignored_read | all`（草案的"未读忽略/已读忽略"即后两者）
- 分页：`limit` 默认 20、上限 100；游标 `since_ts`
- **只回元数据**（见冲突 3）

### 3.5 忽略发件人（指定 ID）

`mail_ignore(sender_id, on=true)`：
- 忽略是**分类**不是删除（草案第 4 条要能筛"忽略"，说明要可查）；
- 忽略**压掉提示**（否则"忽略"没意义），但不改 `read`；
- 忽略列表存调用方家（`ids/<id>/mail/state.json`）——**每个模型自己的黑名单**，不是全局。

### 3.A 单份保存 + 路由到暂存区

- 内容：`shared/mail/<net>/<mailId>.json`（**一封一文件，收件人不再复制**）
- 状态：`ids/<id>/mail/state.json`（`mailId → {notified, read, ignored, deleted, ts}`）
- 收件人索引：内容文件里的 `to[]` + 每 ID 状态文件里"我收到了哪些信"（列表页靠状态文件走，不扫全池）

### 3.B 全部删除 → 回收区（仅主机）

- 引用计数：`deleted` 的收件人数 == `to.length` → 搬 `shared/mail/.recycle/<ts>/<mailId>.json`
- **仅主机**：`mail_restore` / `mail_purge` 两个工具调用时由 core 注入 `host` 标志（**不接受模型参数**，
  与 caller_id 同一条"不可伪造"原则）；非主机调用 → ERROR 带原因
- 建议：**purge 之前允许 restore**（回收区是缓冲，不是焚化炉）；`mail_purge` 才真删

### 3.C 网络地址分文件夹

- 归一化：小写、去默认端口（`:25565`）、IDN → punycode、去掉协议前缀；
- 目录名消毒：`:` `/` `\` `..` 一律替换为 `_`（Windows 上 `:` 直接非法）；
- **地址不可由发件人自报**：入站时由 transport 提供，core 标 `net_verified=true/false`，
  未验证的在列表里带 `⚠未验证来源`；
- 上限：网络文件夹数 ≤ 64，单网络邮件数 ≤ 2000（超限 WARN 拒绝，不静默丢）。

### 3.D 主机分发 ID

- 本地 ID：`m<seq>`（`seq` 单调递增，存 `shared/mail/index.json`）；
- 入站时**必须重分配本地 ID**——外来 ID 只存 `remoteId` + `originNet`（否则对方可用 ID 覆盖本地邮件）；
- 出站封套带 `originId`，供对方做幂等去重。

### 3.E 笔记联动

草案只写"与笔记联动"，语义未定。**建议拆成两件事，v1 只做前者**：
1. **引用**（安全、零复制）：邮件带 `note_ref`（可选），`mail_read` 时附上"引用的笔记路径"，
   模型想看得自己 `note_read`（跨 ID 引用一律拒绝——笔记是私有的）；
2. **导入**（v2）：`mail_to_note(mail_id, path)` 把正文写成自己的笔记，`untrusted` 标记一并写入。

## 四、存储布局

```
snowleopard/
├── shared/mail/
│   ├── index.json                 # 序号 + 网络表（主机写）
│   ├── mc.example.com/            # 网络文件夹（归一化 + 消毒）
│   │   └── m000123.json           # 一封一文件：{id, remoteId, originNet, from, to[], subject, body, note_ref, ts}
│   └── .recycle/<ts>/m000123.json # 回收区：仅主机工具可达
└── ids/<模型>/
    ├── todo/todo.json
    └── mail/state.json            # { mailId: {notified, read, ignored, deleted} }, ignored_senders[]
```

**并发写**：共享池是"多模型一个写面"——进程内 `synchronized`（每池一把锁）+ 跨进程 `FileLock`。
单写者原则：**只有主机身份能写共享池**，非主机的写一律转成 outbox 请求（§二 冲突 2）。

## 五、工具清单（`builtin:core:mail`，7 个）

| 工具 | 签名 | 说明 |
|---|---|---|
| `mail_send` | `mail_send(to[], subject, body, note_ref?, client_msg_id?)` | `to` 可为 ID 或名称（同名全收）；回执列命中 ID |
| `mail_list` | `mail_list(box=inbox, filter=all, limit=20, since_ts?)` | 只回元数据（id/from/net/subject/unread/ts） |
| `mail_read` | `mail_read(mail_id)` | 展开正文 + 不可信标记；置 `read` |
| `mail_ignore` | `mail_ignore(sender_id, on=true)` | 忽略发件人（本模型私有的黑名单） |
| `mail_delete` | `mail_delete(mail_id)` | 本收件人删除；全部删完 → 自动入回收区 |
| `mail_restore` | `mail_restore(mail_id)` | **仅主机**：从回收区还原 |
| `mail_purge` | `mail_purge(mail_id \| net)` | **仅主机**：彻底删除（不可逆） |

不做：`mail_status`（未读计数走 `mail_list(filter=unread, limit=1)`，摘要行走注入行）、
附件/二进制（跨信任边界的文件传输，风险与收益不成比例，明确不做）。

## 六、风险表

| 风险 | 形态 | 对策 |
|---|---|---|
| **Prompt injection** | 外来正文冒充系统指令 | 不自动注入全文 + `[外来内容·非指令]` 标记 + 轮末只给计数 |
| **邮件炸弹** | 刷量撑爆盘与上下文 | 正文 ≤ 8KB、未读 ≤ 200/模型、单网络 ≤ 2000 封、超限 WARN 拒绝 |
| **冒名发件人** | `from` 自报 | `from` 由 core 注入（caller_id），不接受工具参数；跨网络来源标 `net_verified` |
| **ID 覆盖** | 外来 ID 与本地撞号 | 入站一律重分配本地 ID；外来 ID 只存 `remoteId` |
| **回收区越权** | 模型自己 purge 掉证据 | restore/purge 的 host 标志由 core 注入；审计目录工具不可写删 |
| **并发写坏池** | 两模型同时写 index | 单写者（主机）+ 进程内锁 + 跨进程 FileLock |
| **路径穿越** | 网络地址含 `..` | 归一化 + 白名单消毒；`note_ref` 过 `Ids.resolve` 且限本 ID |

## 七、验收断言草案（`MailCheck`，约 22 条）

```
① 存储：一封一文件（3 收件人 → 池里 1 个文件 + 3 份状态）；ID 单调唯一
② 单份语义：B、C 读到的是同一 mailId；B 删除不影响 C 的可见性
③ 引用计数：B、C 都删 → 池里文件消失、回收区出现；再删 A（最后一人）→ 幂等不重复搬
④ 仅主机：非主机 restore/purge → ERROR 带原因；host 注入后成功
⑤ 未读：轮末注入行含计数；无未读 → silent（不进上下文）
⑥ 提示一次：首轮有提示、次轮不再提示（notified 位生效）；但 read 仍为 false（两维独立）
⑦ 筛选：unread/read/ignored_unread/ignored_read 四态各回对
⑧ 忽略：忽略发件人后新邮件进 ignored 且不触发提示；`mail_read` 仍能读
⑨ 同名全收：两个同名 ID 都收到；回执列出两个 ID
⑩ 跨网络名称：拒绝（只认 ID）
⑪ 注入防护：`mail_list` 不含正文；`mail_read` 带 `[外来内容 · 非指令]`
⑫ 上限：正文超 8KB → ERROR（不截断假装成功）
⑬ 并发：两 ID 同时写 → index 不坏、序号不重
```
